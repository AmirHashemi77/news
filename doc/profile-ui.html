توضیح بخش‌هایی که ممکن است ناآشنا باشند

چرا از satisfies Record<string, ProfileSection> استفاده شده؟

این عبارت به TypeScript می‌گوید مقدار تمام کلیدهای تنظیمات باید شامل عنوان، مسیر، توضیح و آیکون معتبر باشد. در عین حال نام کلیدها، مانند edit و saved، مشخص می‌ماند؛ بنابراین نوشتن profileSections.edit ساده و قابل بررسی است. این عبارت در زمان اجرا کاری انجام نمی‌دهد.

Object.values و const Icon = section.icon چه می‌کنند؟

Object.values(profileSections) مقدارهای تنظیمات را به یک فهرست تبدیل می‌کند تا با map ردیف‌های منو ساخته شوند. ترتیب همین پنج کلید متنی در تنظیمات، ترتیب نمایش آن‌هاست. آیکون یک کامپوننت React است؛ آن را در متغیر Icon با حرف بزرگ می‌گذاریم تا بتوانیم با <Icon /> رندر کنیم.

چرا فقط دکمهٔ بازگشت use client دارد؟

این دکمه به window.history و useRouter نیاز دارد. اگر تاریخچه‌ای وجود داشته باشد، router.back() اجرا می‌شود؛ در غیر این صورت router.replace('/profile') مقصد جایگزین است. همین رفتار در عملیات صفحهٔ خبر هم وجود داشت. سایر کامپوننت‌های جدید تعاملی نیستند و Server Component باقی مانده‌اند؛ این عنوان به معنی دریافت داده از Backend نیست.

چرا details در قالب زیرصفحه اختیاری است؟

تنها صفحهٔ ویرایش، چند مقدار نمایشی مانند نام و ایمیل دارد. ارسال اختیاری این فهرست باعث می‌شود همان قالب برای پنج صفحه استفاده شود، بدون اینکه قالب دربارهٔ نوع صفحه شرط‌های متعدد داشته باشد. تگ‌های dl، dt و dd هم رابطهٔ «عنوان مشخصه / مقدار مشخصه» را بیان می‌کنند.

نقش bdi، کلاس‌های واکنش‌گرا و aria-hidden چیست؟

bdi جهت نمایش نام کاربری و ایمیل لاتین را از متن فارسی اطراف جدا می‌کند. پیشوند sm: اندازه‌ها و فاصله‌ها را در نمایشگر بزرگ‌تر تغییر می‌دهد. آیکون‌های تزئینی با aria-hidden از صفحه‌خوان پنهان شده‌اند؛ متن لینک یا برچسب دکمه، نام قابل فهم هر کنترل را فراهم می‌کند.

چه چیزهایی نمایشی هستند؟

  • نام، شناسه، نام کاربری، ایمیل، عکس و نشان عضویت از Mock Data خوانده می‌شوند.
  • عکس در پروژه ذخیره شده و دکمهٔ ویرایش روی آن فقط به صفحهٔ ویرایش می‌رود؛ آپلود تصویر وجود ندارد.
  • صفحهٔ ویرایش فقط اطلاعات خواندنی نشان می‌دهد؛ فرم ذخیره یا درخواست تغییر اطلاعات ندارد.
  • صفحه‌های رمز عبور، خبرهای ذخیره‌شده، بازدیدهای اخیر و نظرها فقط عنوان و توضیح نمایشی دارند.
  • احراز هویت جدید، API، Service، Repository، اتصال دیتابیس و وابستگی جدید اضافه نشده است.

Layout عمومی پروژه همچنان رفتار قبلی خودش را دارد، از جمله منوی کاربر موجود در هدر. صفحهٔ پروفایل جدید اطلاعات واقعی آن منو را دریافت نمی‌کند و بدون افزودن شرط ورود تازه، با دادهٔ نمایشی قابل مشاهده است.

نقاط آماده برای مرحلهٔ اتصال

در مرحلهٔ بعد می‌توان دادهٔ واقعی را به جای mockProfile به UI داد؛ فرم ویرایش و تغییر رمز، فهرست‌های شخصی و سطح دسترسی را داخل همین Feature توسعه داد. تنظیمات مسیر و منو و قالب کلی زیرصفحه‌ها قابل استفادهٔ مجدد هستند.

بررسی نهایی

موفق هر شش مسیر با درخواست واقعی به سرور توسعه بررسی شدند؛ همه پاسخ HTTP 200، عنوان فارسی درست و جهت RTL داشتند. عکس محلی نیز با پاسخ صحیح سرو شد.

موفق پنج گزینهٔ منو در مرورگر کلیک شدند، هرکدام به صفحهٔ خودش رفت و دکمهٔ بازگشت هر پنج صفحه دوباره پروفایل را نمایش داد.

موفق چیدمان در عرض‌های 320px، 390px، 768px و 1440px بررسی شد؛ اسکرول افقی یا بریده‌شدن محتوای پروفایل دیده نشد. نمای موبایل و دسکتاپ نیز از نظر ظاهر بررسی شدند.

موفق ESLint فایل‌های جدید بدون خطا یا هشدار اجرا شد. هر پنج تست موجود پروژه در SelectBox.test.tsx پاس شد. لینک‌های داخلی این مستند هم به بخش‌های معتبر اشاره می‌کنند و فایل HTML مستقیماً در مرورگر باز شد.

کامپایل موفق دستور npm run build -- --webpack اجرا شد و مرحلهٔ کامپایل Webpack موفق بود.

محدودیت موجود بیلد کامل در مرحلهٔ TypeScript با همان سه خطای موجود پیش از شروع این کار متوقف شد. هیچ خطای جدیدی از فایل‌های پروفایل گزارش نشد.

خطاهای قبلی خارج از محدودهٔ پروفایل

  • در src/app/categoryList/page.tsx مقدار newsCategories به‌عنوان export صفحه تعریف شده که از exportهای مجاز App Router نیست.
  • در LatestNewsListSection.tsx و SportNewsListSection.tsx پراپرتی title به NewsList ارسال می‌شود، در حالی که نوع پراپرتی‌های آن این فیلد را ندارد.

بررسی اولیهٔ کل پروژه نیز سه هشدار lint داشت: یک نوع استفاده‌نشده در فایل نوع ورود و دو آیکون استفاده‌نشده در سایدبار. برای حفظ محدودهٔ درخواست، این فایل‌های نامرتبط تغییر نکردند.

npx eslint src/features/user/profile src/app/profile
node --import tsx --test src/shared/ui/selectbox/SelectBox.test.tsx
npm run build -- --webpack
npx tsc --noEmit --incremental false

برای مشاهدهٔ این مستند کافی است همین فایل HTML را در مرورگر باز کنید؛ سرور یا ابزار اضافی لازم نیست. فونت و تصویر از فایل‌های محلی پروژه خوانده می‌شوند.

عکس نمونه از Unsplash دریافت و در پروژه ذخیره شده است. این تصویر و مشخصات نمونه به حساب واقعی کاربر متصل نیستند.
